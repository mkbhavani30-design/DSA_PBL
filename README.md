# Campus Radar – Campus Overflow Study-Room Navigation

When the Central Library is full, Campus Radar finds the nearest free room in Department A or Department B, checks it against a weekly timetable, and guides the student there step by step. Built in C for a Data Structures and Algorithms project-based learning (DSA PBL) course.

## Features

- Campus modelled as a weighted graph (3 buildings, 8 floors, 98 nodes) loaded from `db/campus_map.json`
- Shortest paths with **Dijkstra** and **A\*** (floor-aware heuristic, separate stair and elevator costs)
- **Segment tree with lazy propagation** for booking/releasing rooms and finding free runs
- Weekly timetable (Mon–Fri, Morning/Afternoon) plus live bookings saved to `db/bookings_state.json`
- Tiered fallback: Classroom → Lab → Seminar Hall → Study Zone, ranked by path cost, suitability and user preferences
- Web interface with top-3 closest rooms, preference panel and step-by-step navigation (Back / Move Next / Auto Walk)

## Data Structures and Algorithms

| Component | Use |
|---|---|
| Adjacency-list graph | Campus topology |
| Binary min-heap | Priority queue for Dijkstra and A\* |
| Dijkstra | All-distance queries, optional blocked nodes |
| A\* | Point-to-point routes between rooms |
| Segment tree (lazy) | Range booking and first-free queries in O(log n) |

## Getting Started

### Requirements

- GCC (MinGW-w64 on Windows)
- A modern web browser

### Quick start (Windows)

Double-click `run.bat` in the project root. It builds the backend, starts the server on port 8000 and opens the web app.

### Manual start

```bash
cd backend
make                     # builds campus_backend (campus_backend.exe on Windows)
./campus_backend         # or: campus_backend.exe 8000
```

Then open `frontend/index.html` in your browser. The server must be started from the `backend` folder because it reads `../db/campus_map.json` and `../db/bookings_state.json`. The frontend expects the API at `http://localhost:8000/api` (set in `frontend/app.js`).

Optional arguments: `campus_backend <port> <map_path> <state_path>`

### Run the tests

```bash
cd engine
gcc -O2 -std=c11 -o test_engine test_engine.c segment_tree.c campus.c heap.c campus_router.c map_loader.c -lm
./test_engine
```

The test runs 5,000 random segment tree operations against a brute-force reference and verifies cross-building A\* routing on the real map.

### Demo program

```bash
cd engine
gcc -O2 -std=c11 -o main main.c segment_tree.c campus.c heap.c campus_router.c map_loader.c -lm
./main
```

## API Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/health` | Service status |
| GET | `/api/map` | Campus map |
| GET | `/api/rooms` | Rooms with status for a day and shift |
| GET | `/api/top-rooms` | Top 3 free rooms with paths |
| GET | `/api/nearest-room` | Single best overflow room |
| GET | `/api/route` | Shortest path between two nodes |
| POST | `/api/rooms/book` | Book a room slot |
| POST | `/api/rooms/release` | Release a room slot |
| POST | `/api/library/overflow` | Mark library full or free for a slot |

## Routing and Ranking

- Extra cost per floor change: 5.0 for stairs, 3.0 for elevators
- Room score = path cost + suitability penalty (classroom 0, seminar hall 4, quiet zone 6, lab 9)
- Preferred building: −8, other buildings: +4; lower-floor preference: +1.5 per floor above floor 1

## Limitations and Future Work

- The timetable is generated by a permutation rule, not imported from a real timetable
- A\* runs once per free candidate room; a single multi-target Dijkstra pass would be faster
- Only three buildings are covered

Planned: real timetable import, live occupancy sensing, more buildings, mobile app.
